# fluka-user-manual-and-relevant-guides

Optional, locally-parsed FLUKA/FLAIR reference corpus. This is a **placeholder**, not shipped content — see `README.md` for the licensing policy. Nothing in this folder is required for AutoFLUKA to function.

## Scope

- This is background reference material, not a behavioral skill. It has no dedicated UI toggle and is not one of AutoFLUKA's routed skill lanes (authoring/execution/postprocessing/troubleshooting/subroutines).
- Content here is generated by the visual-parser PDF ingestion pipeline, not hand-authored like the other `SKILL.md` files in `fluka_skills/`.

## How this folder is populated

Run the visual-parser ingestion pipeline against your own licensed FLUKA/FLAIR manual, course notes, or guides. It writes:

- `01_chunks_kb.jsonl` — extracted text chunks
- `02_visuals_kb.jsonl` — extracted figures/diagrams
- `03_metadata_kb.jsonl` — per-document metadata
- `04_processed_pdfs.txt` — ingestion ledger (which source PDFs have been processed)
- `05_pipeline.log` — run log

These three JSONL files are the **canonical, provider-agnostic output**. Anything else derived from them (see below) is a rebuildable cache, not the source of truth.

## Provider-specific vector stores are derived, not canonical

AutoFLUKA queries this corpus through whichever chat model is currently initialized:

- A GPT-initialized session builds/reads a `gpt_vector_store/` here.
- Switching to Gemini or a local embedding model builds its **own** local vector store, generated fresh from the same `01_chunks_kb.jsonl`/`02_visuals_kb.jsonl`/`03_metadata_kb.jsonl` — never from another provider's store directly.
- It's normal for only one provider's vector store to exist at a time. A missing one is rebuilt on demand from the JSONLs, not an error condition.

## Keeping material current across multiple projects

If your reference material changes often, or you want to reuse the same corpus across several AutoFLUKA projects instead of duplicating it into every project's bundled `fluka_skills/`, place it under a directory on your host filesystem instead and point AutoFLUKA at it via the Settings "Skills directory" field (or `AUTOFLUKA_SKILLS_DIR`). On first use, ask the agent to parse it so it registers as discoverable knowledge; re-run parsing whenever the source material changes.

## Not part of the generated set

Any file here that doesn't match the visual-parser naming pattern above (e.g. a stray `.f` Fortran source file) is not pipeline output — likely a leftover artifact from an unrelated drop, safe to remove independently of this skill's content.

## When to use

Consulted automatically in the background whenever generated KB files are present — there is nothing to enable or disable. If this folder has no generated KB files, AutoFLUKA continues normally using its built-in skills.
